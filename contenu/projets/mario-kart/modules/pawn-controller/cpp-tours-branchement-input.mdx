## Course : compter les tours

Sur le circuit, la zone 0 est la ligne d'arrivée, et les zones 1, 2, 3... sont des checkpoints à passer dans l'ordre. Le kart retient le prochain checkpoint attendu dans `NextCheckpoint`, et le tour en cours dans `CurrentLap`.

## Brancher les touches

Avec l'Enhanced Input, il faut deux branchements. D'abord, donner au joueur la liste des touches du kart : c'est le <Terme id="input-mapping-context">Input Mapping Context</Terme> (`KartMappingContext`). Ensuite, dire quelle fonction appeler pour chaque Input Action (`ThrottleAction`, `SteerAction`, `DriftAction`, `JumpAction`).

<CodePasAPas fichier="KartPawn.cpp" debut={176} fin={210}>
  <Etape lignes="176-178" titre="Quand un Controller prend le kart">
    `NotifyControllerChanged` est appelée chaque fois que le kart change de Controller, par exemple quand le joueur en prend possession. C'est le bon moment pour lui donner les touches : à cet instant, on sait enfin **qui** pilote.
  </Etape>
  <Etape lignes="180-181" titre="Est-ce un joueur ?">
    `Controller` peut être un joueur ou une IA. Le <Terme id="cast">Cast</Terme> vers `APlayerController` ne réussit que pour un joueur ; pour une IA, il renvoie <Terme id="nullptr">nullptr</Terme> et on ne fait rien : une IA n'a pas de clavier.
  </Etape>
  <Etape lignes="182-189" titre="Ajouter le Mapping Context">
    Chaque joueur local a un sous-système Enhanced Input. On lui ajoute notre Mapping Context avec la priorité 0. À partir de là, les touches du clavier ou de la manette déclenchent nos Input Actions. Les accolades ferment les deux `if` puis la fonction.
  </Etape>
  <Etape lignes="191-193" titre="SetupPlayerInputComponent">
    Unreal appelle cette fonction pour qu'on branche nos actions. On appelle d'abord la version du parent avec `Super`.
  </Etape>
  <Etape lignes="195-199" titre="Récupérer l'Enhanced Input Component">
    Unreal nous donne un `UInputComponent` générique. On le convertit en `UEnhancedInputComponent`, la version qui sait gérer les Input Actions. Si la conversion échoue (projet mal configuré), on s'arrête au lieu de planter.
  </Etape>
  <Etape lignes="201-203" titre="L'accélérateur">
    <Terme id="bindaction">BindAction</Terme> relie une action et un moment à une fonction. Deux liens : `Triggered` (tant qu'on appuie) appelle `OnThrottle`, `Completed` (quand on lâche) appelle `OnThrottleReleased`.
  </Etape>
  <Etape lignes="205-206" titre="Le volant">
    Même chose pour le volant : `OnSteer` tant qu'on tourne, `OnSteerReleased` quand on lâche.
  </Etape>
  <Etape lignes="208-210" titre="Le drift">
    Ici, on utilise `Started` : une seule fois, au moment de l'appui. Le drift a aussi un `Completed` : c'est en relâchant qu'on obtient le turbo.
  </Etape>
</CodePasAPas>

<CodePasAPas fichier="KartPawn.cpp" debut={214} fin={215}>
  <Etape lignes="214-215" titre="Le saut">
    `Started` aussi : un saut ne doit partir qu'une fois par appui, pas à chaque image tant que le bouton est enfoncé. L'accolade ferme la fonction.
  </Etape>

`this, &AKartPawn::OnThrottle` se lit : « sur cet objet-ci, appelle la fonction `OnThrottle` de la classe AKartPawn ». Le `&` devant le nom donne l'adresse de la fonction, pour qu'Unreal sache laquelle appeler plus tard.

Imagine que tu tiens la touche d'accélération une demi-seconde. Les trois moments, appelés <Terme id="trigger-event">ETriggerEvent</Terme>, se déclenchent ainsi : **Started** une fois quand tu appuies, **Triggered** à chaque image tant que tu tiens la touche, **Completed** une fois quand tu relâches. Un axe qu'il faut suivre en continu utilise Triggered, une action ponctuelle utilise Started.

</Encadre>
